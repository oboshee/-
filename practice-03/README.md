## 3. Эксперименты по DOM и событиям

Перед запуском каждого действия записан прогноз, затем — фактический результат.

| № | Эксперимент | Прогноз | Фактический результат | Объяснение |
|---|-------------|---------|------------------------|------------|
| 1 | Отсутствующий элемент и пустая коллекция | `null` и `0` | `null` и `0` | `querySelector` без совпадений → `null`. `querySelectorAll` → пустой `NodeList` с `length === 0` |
| 2 | `dataset.taskId` у кнопки | строка `"23"`, затем число `23` | `"23" string`, `23 number` | `dataset` хранит строки; `Number()` преобразует в число |
| 3 | Двойное нажатие «Добавить запись» | длина растёт, старая коллекция не меняется | `1 → 2 → 3`; старая коллекция осталась `1` | `querySelectorAll` возвращает **статическую** коллекцию, для нового снимка нужен новый запрос |
| 4 | Клик по «Изменить заголовок» | `<strong>` покажется как текст | `<strong>Это текст, а не HTML</strong>` | Используется `textContent`: HTML не интерпретируется, теги видны как текст |
| 5 | Клик по вложенному `span` | фазы 1→2→3; `target` — span, `currentTarget` меняется | phase=1, phase=3, phase=3; `target=lab-label`, `currentTarget=lab-card → lab-button → lab-card` | Событие всплывает от вложенного элемента к предкам. `target` — где произошло, `currentTarget` — где выполняется обработчик |

## 4. Распределение ответственности между модулями

| Модуль | Ответственность |
|--------|-----------------|
| `src/data.js` | Исходные данные: `demoTasks`, `variantTasks`, `variantNumber` |
| `src/task-service.js` | Прикладные функции из ПР2 (создание, поиск, изменение, удаление) |

| `src/main.js` | Состояние (`currentTasks`, `currentFilter`), обработчики событий, вызовы сервиса и отрисовки |

| Шаг | Действие и фильтр | Видимые id | Всего | Выполнено | Осталось | Прогресс |

| 1 | Выбрать «В работе» | [4, 7] | 4 | 2 | 2 | 50.0% |
| 2 | Отметить выполненной id = 4 | [7] | 4 | 3 | 1 | 75.0% |

| 6 | Выбрать «Все», переключить id = 1 | [1, 4, 10] | 3 | 2 | 1 | 66.7% |
| 7 | Последовательно удалить 1, 4, 10 | [] | 0 | 0 | 0 | 0.0% |

**Отладка через DevTools:**

- Точка останова на строке чтения `dataset.taskId` в `handleTaskListClick`: `dataset.taskId` = `"4"` (string), после `Number(...)` — `4` (number).
- Проверка отказа: временная замена `data-task-id` карточки на `777` — при клике сообщение «Задача не найдена», массив не изменён.
- Проверка отказа: замена на `4abc` — сообщение «Некорректный идентификатор задачи».
- Путь события: клик по вложенной подписи кнопки → `closest("button[data-action]")` находит кнопку, `closest("li[data-task-id]")` находит карточку.

## 9. Вывод

В ходе работы:

- Освоено создание DOM-элементов через `createElement`, `append`, `replaceChildren`.
- Реализовано делегирование событий через `closest` и один обработчик на контейнер.
- Названия и сообщения выводятся через `textContent` — HTML не интерпретируется.
- Состояние разделено: `currentTasks` (полный массив) и `currentFilter` (режим отображения).
- Использованы функции ПР2 (`findTaskById`, `setTaskCompleted`, `removeTask`, `getTaskStats`) без дублирования логики.
- Все 35 проверок сервиса и 36 браузерных проверок пройдены.
- Общий и индивидуальный сценарии выполнены, результаты зафиксированы.
